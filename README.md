# MythicTavern

Локальная мастерская ролевых приключений с ИИ-ведущим. Конкурсный прототип, объединяющий чат, персонажей, кубики, базу знаний мира и историю кампании в одном интерфейсе.

## Идея и ценность

Во время ролевой игры описание мира, листы героев, заметки о NPC и результаты бросков обычно находятся в разных местах. MythicTavern собирает их в одном рабочем пространстве и передаёт выбранной языковой модели контекст текущего приключения.

Интерфейс и сервер приложения запускаются локально. Для генерации можно подключить локальную модель через LM Studio/Ollama либо использовать внешний Gemini API. Локальный запуск приложения сам по себе не означает, что выбранная модель тоже работает локально.

Цель проекта — помочь вести небольшое приключение и развивать идею разделения художественного повествования и проверяемых игровых последствий. Это не законченный автоматический мастер и не полная реализация правил D&D.

## Что демонстрирует прототип

- Выбор приключений и управление кампаниями.
- Листы персонажей, HP, инвентарь и состояния.
- Чат с выбранной моделью от лица отдельных героев или совместного хода.
- Броски кубиков и карточки запрошенных проверок.
- База знаний мира: NPC, локации, предметы, фракции и квесты.
- Подбор релевантного лора и приблизительная оценка контекста.
- История, хроники и экспорт/импорт кампании.
- Экспериментальная обработка структурированных событий урона.

Наличие экрана или функции не означает, что все её сценарии уже проверены. Ограничения перечислены ниже; автоматический бой не заявляется как готовая возможность.

## Текущее состояние

Рабочая ветка: `fix/tavern-stability`.

При подготовке документации в ветке присутствуют `package-lock.json` и `esbuild` версии `0.28.0`; прежний конфликт с `^0.25.0` не следует исправлять повторно по старым инструкциям. В корне также проверены исправленные импорты `ChatArea.tsx`. Полную проверку остальных импортов нужно подтвердить командами ниже.

На локальной копии автора подтверждены запуск интерфейса, получение ответа модели и прохождение восьми тестов модуля событий урона. Полная проверка чистого клона, интеграционных сценариев и всех провайдеров ещё не выполнена.

## Быстрый запуск

Понадобятся Git, Node.js и npm. Версия Node.js должна соответствовать требованиям установленных Vite и зависимостей. Для воспроизводимой проверки сохраните вывод `node --version` и `npm.cmd --version`.

### Windows / PowerShell

```powershell
git clone --branch fix/tavern-stability https://github.com/LoreOfMetal11/AI_Tavern_HAKATON.git
cd AI_Tavern_HAKATON
npm.cmd ci
npm.cmd run dev
```

Откройте `http://localhost:3000`. Терминал с сервером должен оставаться открытым; остановка — `Ctrl+C`. Если задана переменная `PORT`, используйте соответствующий порт.

`npm.cmd` и `npx.cmd` позволяют выбрать Windows-командные обёртки вместо PowerShell-файлов `npm.ps1`/`npx.ps1`. Менять политику выполнения сценариев для этих команд не требуется.

### Linux / macOS

```bash
git clone --branch fix/tavern-stability https://github.com/LoreOfMetal11/AI_Tavern_HAKATON.git
cd AI_Tavern_HAKATON
npm ci
npm run dev
```

Используйте `npm ci` с закоммиченным lock-файлом. Если установка не проходит, сохраните сообщение об ошибке; не обходите проверку через `--force` или `--legacy-peer-deps`. Изменение зависимостей с `npm install` должно сопровождаться проверкой и обновлением lock-файла.

Проверка сервера отдельно от UI: `http://localhost:3000/api/health` должен вернуть JSON с `status: "ok"`. Это не проверка модели.

Для разработки запускайте `npm run dev`: Express предоставляет игровые API и подключает Vite. `npm run preview` сам по себе не заменяет Express-сервер. Production-запуск ещё требует отдельной проверки; текущий `npm start` вызывает `node server.ts`.

## Подключение модели

### LM Studio — основной локальный демо-сценарий

1. Установите и загрузите выбранную модель в LM Studio.
2. Запустите её локальный сервер.
3. В таверне откройте «Настройки ИИ → Подключение».
4. Выберите `lmstudio`.
5. Укажите базовый адрес `http://localhost:1234/v1`, либо свой адрес и порт.
6. Укажите точный идентификатор модели, принимаемый сервером.

Таверна добавляет `/chat/completions`. Итоговый запрос должен идти на `/v1/chat/completions`, не на `/chat/completions` и не на нативный `/api/v1/chat`. При ошибке `Unexpected endpoint or method. (POST /chat/completions)` проверьте окончание `/v1`.

Если сервер не требует авторизации, ключ Gemini для этого сценария не нужен. Модель и её файлы не входят в репозиторий; их нужно установить отдельно.

### Ollama

Выберите `ollama`, укажите `http://localhost:11434/v1` и точное имя установленной модели. Убедитесь, что сервер доступен. Этот провайдер не следует считать проверенным на всех моделях только по наличию настройки.

### Gemini — внешний сервис

Выберите `gemini`, укажите собственный API-ключ и доступный вашему аккаунту идентификатор модели. Стартовое имя `gemini-3.8-flash` не подтверждено успешным API-запросом при проверке проекта.

Ключ можно ввести в интерфейсе либо задать серверу через `GEMINI_API_KEY`. В репозитории есть безопасный шаблон `env.example`. Если нужен файл окружения:

```powershell
Copy-Item env.example .env
```

Впишите собственный ключ только в локальный `.env`. Сервер использует `dotenv.config()` и не настроен отдельно на чтение `.env.local`. Для LM Studio/Ollama создавать `.env` с ключом Gemini не требуется.

### Демо-симулятор

В активном сервисе ходов симулятор явно сообщает, что настоящая модель не подключена. Он не разрешает произвольные действия и не изменяет HP. Это не замена реальной модели для демонстрации повествования.

## Рекомендуемый сценарий демонстрации

1. Открыть первое приключение с готовыми героями.
2. Показать панель партии и лист персонажа.
3. Открыть базу знаний и показать запись о локации или NPC.
4. Подключить выбранную локальную модель.
5. Отправить: «Спрашиваю стражника, почему закрыты ворота».
6. Показать фактический ответ на действие.
7. Продемонстрировать отдельный бросок кубиков и историю сообщений.
8. Объяснить экспериментальный статус автоматической механики и дальнейший план.

Для конкурсного видео показывайте настоящее поведение. Ручное изменение HP нельзя выдавать за автоматический расчёт, а заранее подготовленный текст — за ответ модели. Перед живым показом проверьте этот сценарий на выбранной модели. Требования к ролику, исходникам, лицензиям и раскрытию использования ИИ определяются правилами конкретного конкурса.

## Проверки

Из корня проекта, по отдельности:

```powershell
npm.cmd run lint
node --test turnMechanics.test.mjs
npx.cmd --no-install tsx --test rules.test.ts
npm.cmd run build
```

В Linux/macOS используйте `npm` и `npx` без `.cmd`.

`lint` запускает `tsc --noEmit`. Скрипта `npm test` пока нет. Для `turnMechanics.test.mjs` подтверждён результат `8 passed / 0 failed`; это модульные тесты, не проверка полного игрового пути.

Если появляются `TS2307` для `../types/dnd`, `../utils/rules` или `../data/galleryAssets`, проверьте, что все исправления исходников попали в сдаваемую ветку. При текущей плоской структуре используются `./dnd`, `./rules` и `./galleryAssets`. Не отключайте строгую проверку типов ради обхода ошибок.

`npm audit` показывает найденные уязвимости. Не запускайте `npm audit fix --force` без анализа изменений. Предупреждения об install scripts рассматривайте отдельно через `npm install-scripts ls`, не одобряя всё автоматически.

## Архитектура

```text
React UI
  → App.tsx: состояние и ход
  → dmTurnService.ts: контекст и запрос
  → server.ts: Express API-прокси
  → локальная модель или Gemini
  → parseAiResponse / turnMechanics.mjs
  → проверка события, изменение HP и история
```

| Файлы | Назначение |
| --- | --- |
| `main.tsx`, `index.html` | Запуск React |
| `App.tsx` | Кампании, партия, сообщения, сохранение |
| `dmTurnService.ts` | Активный сервис генерации и бюджета контекста |
| `llmService.ts` | Прежний сервис и используемый парсер ответа |
| `turnMechanics.mjs` | Разбор, проверка и применение событий урона |
| `rules.ts`, `dnd.ts` | Общие функции и типы |
| `defaultCampaigns.ts`, `galleryAssets.ts` | Стартовые данные и галерея |
| `ChatArea.tsx`, `PartySidebar.tsx`, `*Modal.tsx` | Интерфейс |
| `server.ts` | Express, API и Vite middleware |

Исходники сейчас находятся в корне. Состояние хранится в `localStorage` конкретного браузера: это не общая серверная база и не сетевой мультиплеер. Экспортируйте кампанию перед очисткой данных браузера.

## Известные ограничения

### Повествование и игровые последствия

Автоматический урон зависит от корректного события `<damage_event>...</damage_event>`, возвращаемого моделью. Если она пропустит событие, возможен текст о попадании без изменения HP. Такой дефект воспроизведён при атаке Торгрима по Эльдрину. Поэтому полноценный автоматический бой не заявляется готовым.

Проверка цитат подтверждает наличие текста в переданном контексте, а не правильность всех выводов модели. Проверки вопросов, отрицаний и лавы эвристические. Полные правила оружия, сопротивлений, состояний, спасбросков, временных HP, смерти и восстановления не реализованы.

При корректном событии код изменяет HP и добавляет блок `[Механика]`. Изменение истории и сжатие сообщений с применённым уроном временно блокируются: отката событий пока нет. HP и история сохраняются отдельно, без атомарной транзакции.

Подготовленный базовый PvP-обработчик дубины и одноручного боевого молота в ветку ещё не записан. Не считайте `playerCombat.mjs` и его тесты частью текущей сдаваемой версии.

### Интерфейс и сохранения

- Возможны оставшиеся неверные пути к изображениям, в том числе в пресетах, портрете мастера и старых сохранениях.
- В пустой партии форма первого героя может не открываться; для демо используйте проверенное приключение с готовыми героями.
- Поддержку слотов `A–D` ещё нужно согласовать во всех компонентах.
- Импорт не проверяет полную схему данных; удалённые стартовые сущности могут добавляться обратно при загрузке.
- Сжатие истории пока обрезает сообщения, а не создаёт полноценное резюме с гарантией сохранения событий.
- Часть настроек интерфейса не полностью влияет на генерацию.

### Подключение

- Старая кнопка тестирования локального соединения отправляет неподходящий запрос к `/models`; проверяйте настоящий ответ через чат.
- Клиентский тайм-аут — 130 секунд, прокси локальной модели — 120 секунд.
- Для Gemini пока сохраняется серверный лимит 10 секунд и нет полноценной отмены SDK-запроса.
- Оценка токенов приблизительная и не использует токенизатор каждой выбранной модели.

## Секреты и безопасность подачи

- В проверенном корне текущей ветки нет настоящего `.env`; `env.example` содержит заглушки и оставлен намеренно. Это не аудит всей истории и всех файлов на секреты.
- `.gitignore` исключает `.env`, `.env.*`, зависимости, сборку, логи и резервные копии. Он не удаляет ранее закоммиченные файлы и не очищает историю Git.
- Если реальный ключ когда-либо попадал в коммиты или публичные материалы, отзовите/замените его у провайдера. Удаления файла из последней версии недостаточно.
- Не отправляйте секреты, `.env` и личные сохранения с конкурсным архивом. `.gitignore` не защищает архив, собранный вручную из всей локальной папки.
- API-ключ из интерфейса сейчас сохраняется в настройках `localStorage`; используйте отдельный профиль браузера для показа и не раскрывайте содержимое хранилища на видео.
- Не публикуйте текущий сервер в Интернет: аутентификация и ограничения назначения API-прокси ещё не реализованы.
