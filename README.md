# MythicTavern — локальная мастерская D&D с ИИ

Прототип приложения для проведения ролевых приключений: чат с ИИ-ведущим, персонажи партии, кубики, база знаний мира и история кампании. Интерфейс и сервер приложения запускаются на компьютере пользователя; генерацию можно направить в локальную модель или Gemini.

## Статус проекта

Документация описывает код ветки `fix/tavern-stability` на основе коммита `69bbafb` и результаты локальной проверки 12 ноября 2026 года. Это рабочая ветка разработки, а не проверенный релиз.

Важно различать три состояния:

| Состояние | Что к нему относится |
| --- | --- |
| В GitHub | Серверный прокси, тайм-ауты, явные ошибки API, модуль событий урона и его подключение к чату, часть исправлений импортов и изображений |
| Исправлено только на локальной копии при проверке | Версия `esbuild` изменена на `^0.28.0`; исправлены импорты девяти оставшихся компонентов |
| Подготовлено, но НЕ закоммичено | Отдельный базовый PvP-обработчик дубины и одноручного боевого молота с расчётом попадания и урона |

Чистый клон ветки пока может не установиться или не собраться без описанных ниже исправлений. Запуск интерфейса на локальной копии подтверждён пользователем после исправления зависимостей и импортов. Полная интеграционная проверка ветки, CI и проверка всех игровых сценариев ещё не выполнены.

## Общая идея

Цель — дать небольшой группе удобное пространство для настольной игры с ИИ-ведущим:

- создавать и переключать приключения;
- вести листы персонажей, HP, инвентарь и состояния;
- отправлять действия отдельных героев или совместный ход;
- выполнять броски кубиков;
- хранить NPC, локации, предметы и квесты в базе знаний;
- передавать модели релевантные факты и недавнюю историю;
- отделять художественное описание от изменения игрового состояния.

Ключевой принцип дальнейшей разработки: модель предлагает события и повествование, а проверяемые игровые последствия применяет код. Одной фразы «ты получил ожог» недостаточно для изменения HP. Заявка «атакую» также не должна автоматически считаться попаданием.

Это не полноценный движок всех редакций D&D и не замена проверки правил мастером.

## Архитектура

```text
React-интерфейс
  → App.tsx: состояние кампании и обработка хода
  → dmTurnService.ts: контекст, запрос к модели, разбор ответа
  → Express server.ts: /api/gemini/chat или /api/proxy/llm
  → Gemini либо локальный OpenAI-совместимый сервер
  → проверка событий в turnMechanics.mjs
  → изменение HP и запись результата в историю
```

### Основные файлы

| Файл | Назначение |
| --- | --- |
| `main.tsx`, `index.html` | Точка входа React |
| `App.tsx` | Кампании, персонажи, сообщения, сохранение и обработка ходов |
| `dmTurnService.ts` | Активный сервис генерации ходов, приблизительный бюджет контекста и разбор событий |
| `llmService.ts` | Прежний сервис и вспомогательный парсер; новый сервис использует `parseAiResponse` из него |
| `turnMechanics.mjs` | Разбор и проверка событий урона, изменение HP |
| `turnMechanics.test.mjs` | Восемь тестов модуля событий |
| `rules.ts`, `rules.test.ts` | Общие функции правил, подбор лора и существующие тесты |
| `dnd.ts` | Типы данных |
| `defaultCampaigns.ts` | Стартовые кампании, персонажи, лор и настройки |
| `galleryAssets.ts` | Галерея изображений и оформление настроений |
| `ChatArea.tsx`, `PartySidebar.tsx`, `*Modal.tsx` | Чат, панель партии и модальные окна |
| `server.ts` | Express, API-прокси и Vite в режиме разработки |

Сейчас исходники лежат в корне репозитория. Пути наподобие `../types/dnd`, `../utils/rules`, `../data/galleryAssets` для этой структуры неверны.

Состояние сохраняется в `localStorage` браузера. Это не общая серверная база и не реализованная синхронизация нескольких игроков по сети. Не очищайте данные браузера без резервной копии кампании.

## Установка зависимостей

В `package.json` на момент написания README ещё указан `esbuild: ^0.25.0`. При локальной установке Vite `8.3.8` потребовал `esbuild: ^0.27.0 || ^0.28.0`, что вызвало `ERESOLVE`. Подтверждённое локальное исправление:

```powershell
npm.cmd pkg set "devDependencies.esbuild=^0.28.0"
npm.cmd install
```

После записи совместимых зависимостей и lock-файла в репозиторий этот обходной шаг нужно убрать из инструкции. Не удаляйте lock-файл и `node_modules` без необходимости.

Не запускайте `npm audit fix --force` вслепую. Сначала прочитайте отчёт:

```powershell
npm.cmd audit
```

Предупреждение `install-scripts ... not yet covered by allowScripts` требует отдельного рассмотрения, а не автоматического одобрения всех скриптов:

```powershell
npm.cmd install-scripts ls
```

## Временное исправление оставшихся импортов

Если после установки `npm.cmd run lint` сообщает `TS2307` для `../types/dnd`, `../utils/rules` и `../data/galleryAssets`, выполните блок ниже из корня проекта. Он меняет только точные строковые пути в корневых `.tsx`-файлах и сохраняет исходники с расширением `.bak`.

```powershell
$root = (Get-Location).Path
foreach ($required in @("dnd.ts", "rules.ts", "galleryAssets.ts", "package.json")) {
    if (-not (Test-Path -LiteralPath (Join-Path $root $required))) {
        throw "Не найден $required. Откройте терминал в корне проекта."
    }
}
$replacements = @{
    "../types/dnd" = "./dnd"
    "../utils/rules" = "./rules"
    "../data/galleryAssets" = "./galleryAssets"
}
$backup = Join-Path $root ("imports-backup-" + (Get-Date -Format "yyyyMMdd-HHmmss-fff"))
$utf8 = [System.Text.UTF8Encoding]::new($false)
Get-ChildItem -LiteralPath $root -File -Filter "*.tsx" | ForEach-Object {
    $file = $_
    $original = [System.IO.File]::ReadAllText($file.FullName)
    $updated = $original
    foreach ($oldPath in $replacements.Keys) {
        $newPath = $replacements[$oldPath]
        $updated = $updated.Replace(("'" + $oldPath + "'"), ("'" + $newPath + "'"))
        $updated = $updated.Replace(('"' + $oldPath + '"'), ('"' + $newPath + '"'))
    }
    if ($updated -cne $original) {
        if (-not (Test-Path -LiteralPath $backup)) {
            New-Item -ItemType Directory -Path $backup | Out-Null
        }
        Copy-Item -LiteralPath $file.FullName -Destination (Join-Path $backup ($file.Name + ".bak"))
        [System.IO.File]::WriteAllText($file.FullName, $updated, $utf8)
        Write-Host "Исправлен: $($file.Name)"
    }
}
```

Не добавляйте папку резервных копий в коммит. Не отключайте строгую проверку типов и не заменяйте все ошибки на `any`: часть ошибок вывода типов исчезает после восстановления правильных импортов.

Эта процедура не исправляет оставшиеся строковые пути к изображениям. Они перечислены в задачах ниже.

## Подключение ИИ

### LM Studio

1. Загрузите выбранную модель в LM Studio и запустите локальный сервер.
2. В таверне откройте настройки подключения.
3. Выберите провайдер `lmstudio`.
4. Укажите базовый адрес `http://localhost:1234/v1` либо свой адрес и порт.
5. Укажите точный идентификатор модели, который принимает ваш сервер.

Таверна дописывает `/chat/completions`. Итоговый маршрут должен быть `/v1/chat/completions`. Если в логах видно `Unexpected endpoint or method. (POST /chat/completions)`, проверьте окончание `/v1` в настройках. Нативный маршрут `/api/v1/chat` не является прямой заменой для текущего формата запросов.

### Ollama

Выберите `ollama`, укажите `http://localhost:11434/v1` и точное имя установленной модели. Убедитесь, что сервер запущен. Не копируйте имя модели из примера, если она не установлена.

### Gemini

Выберите `gemini` и укажите ключ в настройках либо задайте на сервере `GEMINI_API_KEY` через окружение или `.env`. Текущий `server.ts` вызывает `dotenv.config()` без отдельной настройки `.env.local`; не рассчитывайте, что сервер прочитает `.env.local` автоматически.

Стартовое имя `gemini-3.8-flash` не подтверждено реальным успешным API-запросом в рамках проверки проекта. Укажите доступный вашему аккаунту точный идентификатор модели. Не публикуйте ключи в чатах, репозитории или скриншотах. Перед использованием `.env` добавьте его в `.gitignore`.

### Симулятор

В активном сервисе ходов это диагностический деморежим: он явно сообщает, что настоящая модель не подключена, и не изменяет HP. Он не подходит для проверки свободного повествования или боевой механики.

### Ограничения подключения

- Клиентское ожидание ограничено 130 секундами; автоматического повтора напрямую мимо прокси нет.
- Прокси локальной модели ограничен 120 секундами.
- У Gemini в серверном коде пока сохраняется отдельный лимит 10 секунд; полноценная отмена SDK-запроса не реализована.
- Старая кнопка проверки соединения в `SettingsModal.tsx` всё ещё отправляет неподходящий запрос к `/models` для локальных провайдеров. До исправления проверяйте настоящий ответ через игровой чат.

## Проверки

Выполняйте отдельно, сохраняя вывод первой упавшей команды:

```powershell
npm.cmd run lint
node --test turnMechanics.test.mjs
npx.cmd --no-install tsx --test rules.test.ts

```

`lint` — это `tsc --noEmit`. Скрипта `npm test` в текущем `package.json` пока нет. Для восьми тестов `turnMechanics.test.mjs` пользователь подтвердил результат `pass 8 / fail 0`. Это модульные тесты, а не подтверждение работоспособности всей игры.

### Ручные сценарии

Используйте отдельную тестовую кампанию или предварительно экспортируйте основную.

| Сценарий | Ожидаемое поведение |
| --- | --- |
| Обычный разговор | Ответ относится к последнему сообщению, HP не меняются |
| Быстрая повторная отправка | Не запускаются параллельные ходы |
| Вопрос «Что будет, если коснуться лавы?» | Не применяется урон за гипотезу |
| Отрицание контакта | Не применяется урон за распознанное отрицание |
| Контакт с подтверждённой опасностью | Корректное событие меняет HP и появляется блок `[Механика]` |
| Лава не установлена в сцене | Нельзя обосновать урон от лавы цитатой про обычные ворота |
| Обновление страницы после урона | Сохраняются HP и событие в истории |
| Перегенерация истории с уроном | Выводится пояснение о временной блокировке, HP не списываются повторно |
| Ошибка модели | Выводится ошибка, а не скрытое продолжение симулятором |

Если модель описала попадание/ожог, но HP не изменились и нет записи `[Механика]`, тест НЕ пройден. Не исправляйте это скрытым ручным списанием: зафиксируйте исходное действие, ответ, HP до/после и ошибку интерфейса.

## Как сейчас применяется урон

Модель должна вернуть вместе с повествованием служебный тег:

```text
<damage_event>{"characterId":"ID героя","amount":5,"reason":"причина","sourceId":"ID источника","sourceQuote":"цитата из сцены","actionQuote":"цитата текущего действия"}</damage_event>
```

Число 5 — пример формата, не правило урона. `amount` означает итоговую величину урона, а не новое значение HP. Код проверяет форму события, цель, величину, цитаты, распознаваемые вопросы/отрицания и специальный случай лавы. Далее HP ограничиваются снизу нулём, а событие сохраняется в сообщении мастера.

Ограничения этой реализации:

- Если модель пропустит тег, пустой список событий сейчас принимается: возможен текст о попадании без изменения HP. Такой случай уже воспроизведён при атаке Торгрима по Эльдрину.
- Цитата из сцены подтверждает наличие текста, но не доказывает корректность всех причинно-следственных выводов модели.
- Проверки отрицаний и лавы эвристические и не являются полноценным разбором языка.
- Код не вычисляет автоматически все правила сопротивлений, уязвимостей, спасбросков, временных HP, смерти и восстановления.
- HP и история сохраняются отдельными операциями `localStorage`, а не одной атомарной транзакцией.
- Полного отката механики нет, поэтому затрагивающие урон изменения истории и сжатие таких сообщений блокируются.
